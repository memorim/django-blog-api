# Независимые логические резервные копии

`scripts/database_backup.py` сохраняет согласованный снимок Django в отдельном PostgreSQL-проекте. В одной read-only repeatable-read транзакции читаются данные и список миграций. Архив gzip, SHA-256, число записей по моделям и версия исходников сохраняются атомарно в `django_backup_snapshots`.

Передайте соединения через окружение: `SOURCE_DATABASE_URL` и `BACKUP_DATABASE_URL`. Они должны вести в разные проекты. Используется verify-full TLS с системными корнями доверия. База копий содержит приватные данные: доступ к ней выдаётся только оператору, значения соединений не входят в Git.

```bash
SOURCE_REVISION=$(git rev-parse HEAD) python scripts/database_backup.py backup
```

Для проверки задайте `RESTORE_DATABASE_URL` нового пустого PostgreSQL в независимом проекте и выберите точный номер снимка:

```bash
python scripts/database_backup.py restore-check --snapshot 1
```

Команда отказывается работать с исходным проектом или непустой базой. Она применяет миграции, сверяет их список, восстанавливает данные и сравнивает SHA-256 канонической сериализации. Пользователи, права, статьи, категории, комментарии, хеши токенов, сессии и счётчики запросов включены; автоматически создаваемые content types и permissions восстанавливаются миграциями. Медиафайлы и секреты окружения сохраняются отдельно.

Код проверен локально; исходящая PostgreSQL-связь из среды разработки недоступна из-за DNS. Создание полной живой копии через доступный облачный интерфейс остановлено автоматической проверкой: требуется отдельное разрешение на перенос приватных данных, включая хеши паролей, токены, сессии, статьи и комментарии, в независимый проект владельца. Живая копия, восстановление и расписание пока не подтверждены. Наличие скрипта не означает, что резервирование уже включено.
