# Проверка опубликованного backend — 07.11.2026

API: https://memorim-django-blog-api.onrender.com/api/articles.
Размещён Python backend на Render Free с отдельной PostgreSQL 16 в Neon Free.
Пароль базы и случайный ключ приложения заданы в окружении хостинга после
разрешения владельца; в исходниках их нет. Подключение к PostgreSQL использует
verify-full и системное хранилище доверенных сертификатов.

На реальном HTTPS адресе проверены:

- Получение списка статей и заголовок HSTS на ответах, включая ошибки.
- Закрытые API docs (404) и запрет анонимной записи (401).
- Регистрация синтетического пользователя, вход, создание и чтение статьи.
- Обновление с текущей версией, 428 без предусловия и 412 с устаревшей версией.
- Выход и отклонение отозванного токена.
- Наличие записи и права чтения у владельца базы после обновления приложения.

Первый запуск выявил ослабление ETag на пути через сжатие/прокси. Добавлены
канонический X-Resource-Version и запрет промежуточной трансформации ответа;
слабые If-Match по-прежнему не принимаются. После публикации исправления
сквозной сценарий создания/обновления и отзыва токена прошёл. Регрессия с
настоящим GZipMiddleware проверяет эту ситуацию отдельно.

Локально прошли 48 тестов Django (два теста блокировок PostgreSQL выполняются
в CI), production-settings, OpenAPI-контракт и обновление предыдущей схемы.
Полный GitHub CI с PostgreSQL также прошёл. Повторяемая проверка:
`tests/check_live_deployment.py`; её закрытый state-файл держите вне Git.

Render Free может засыпать, общий лимит бесплатных часов относится ко всему
workspace. Neon Free сохраняет базу вне файловой системы Render и даёт
шестичасовое окно instant restore; автоматические snapshot-расписания в
текущем плане отсутствуют. Более длинное резервирование настраивается отдельно.
